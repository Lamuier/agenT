# 启动与性能

业务代码集中在 `app`；`performance` 是独立的 Android 测试模块，不提供用户功能。构建与显式采集命令统一见 [build.md](../build.md#性能采集与编译配置)。

## 启动与运行路径

- 主题、语言和启动目标确定后，两个服务在 IO 线程恢复本地凭据与缓存，独立的用量、任务及公开状态并行读取。Keystore 和仓库内部存储按需初始化，不在 ViewModel 构造时加载；选中账号没有变化时不重复写盘。
- 首帧等待目标页面的本地恢复与组合，保留直接显示缓存内容的体验；恢复失败进入可操作状态。实际绘制后仅报告一次 `reportFullyDrawn`，再启动前台网络刷新、小组件维护、动态预览和历史订阅。启动跟踪只使用固定标签，不记录身份、凭据或响应。
- 本机观察历史只在用量页可见时订阅：当前服务按 7 / 30 / 90 天读取，另一服务只读取节奏估算所需的一天。变更通知按服务区分；按文件时间与长度复用解码结果，写入、清空和过期清理同步失效。缓存最多保存 182 个日文件的解析对象，内存压力时清理，历史查询仍限制最近 90 天，过期 UTC 日文件在读取或写入时清理。
- 图表按数据、指标、尺寸和主题缓存降采样点与路径；选择标记只重绘，精确采样选择使用有序查找，保留峰值、缺测及跨周期断点。模型、任务和状态排序复用结果；后台和不可见页面停止时钟工作，首帧后才预加载相邻页。
- Cursor 常规刷新只查询当前用量所需的数据；其他历史区间与比较由用量页按需请求。Codex 用量及公共重置共享同一身份 / 修订号的在途请求，完成后不把结果当作永久缓存；清理后的旧请求不能写回。
- 同批小组件缓存重绘合并约 200 毫秒内的请求，保持最新一代快照。通知复用仓库实例，同一语言只维护一次渠道文案；阈值、重置和任务结束告警不进入重绘合并队列，仍执行原去重与到期规则。

## 可重复验证

`performance` 使用 Macrobenchmark 与 Baseline Profile 稳定工具链。离线夹具只进入 `benchmarkRelease` / `nonMinifiedRelease`，包含两个服务的加密缓存、300 个任务和 90 天观察历史；合成凭据不能用于服务登录。测试模拟器禁用联网，不读取真实凭据。

冷启动分别覆盖空配置、双服务缓存、任务快捷入口和启用编译配置的缓存启动，每项运行 20 次；滚动场景覆盖五个页签及设置。启动指标区分首帧 TTID 与本地可交互完成 TTFD，滚动采集帧耗时。配置由实际操作生成，启动路径单独标记为 Startup Profile，夹具代码被过滤。

普通构建复用保存在源码中的配置，不隐式启动设备或重新采集。显式性能入口要求指定 `emulator-端口`，核对 qemu 身份，并要求隔离的 adb 服务仅连接该模拟器；不选择实体设备。原始 JSON 与跟踪文件保存在 `app/build/reports/performance/`，报告记录模拟器 API / ABI 和环境限制。

前后对照必须使用同一 AVD、窗口、数据、编译模式和迭代次数，并避免其他构建占用主机资源。模拟器结果只用于该环境下的相对对照，不能外推手机耗时、续航或厂商系统表现。Android 方法见[启动指标](https://developer.android.com/topic/performance/issues/launch-time)、[编译配置生成](https://developer.android.com/topic/performance/baselineprofiles/create-baselineprofile)和[性能测量边界](https://developer.android.com/topic/performance/baselineprofiles/measure-baselineprofile)。
