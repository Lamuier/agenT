# 桌面小组件

七种组件保留原 provider 标识，升级后无需重新添加。两种用量组件支持 Cursor、Codex、DeepSeek API 和 Kimi Code。五种状态组件使用这四家的公开健康数据。

## 配置与布局

只展示已保存连接的来源，顺序为 Cursor、Codex、DeepSeek、Kimi Code。认证失败的已保存连接仍显示修复提示；残留公共状态缓存不能让未配置来源重新出现。全部未配置时点击统一配置入口。指向已移除来源的分页锚点在启动时清除。

宿主至少 250×200 dp 且字号不超过 130% 时，4×3 组件改为单页总览，不再分页：

- 用量（二至四个来源）：标题写明「已用额度」，大标题突出用量最高的额度窗口，例如「Codex 5小时 · 已用 100%」，副标题给出该窗口的重置时间和同来源另一窗口。下方每个来源一行，每个百分比前都标注窗口名称（自有 / 三方、5小时 / 每周），并配有额度条。余额只显示币种和金额；单币种 DeepSeek 在金额下注明赠送 / 充值，不再写「余额可用」。空间不够时依次省略大标题的说明行、副标题和整个大标题。
- 状态（一至四个来源）：可在「设置 → 系统入口」的 4×3 服务状态预览下选择三种版式，切换后已放置的组件立即用缓存重绘。「总览列表」先用大标题给出结论，再逐行列出各来源的组件正常数和状态。「四格信号灯」每个来源一格，异常格染色并排在前面，三个来源时异常来源占满首行。「异常置顶」只展开有问题的来源，卡片写明事件、持续时长和受影响组件，正常来源折叠成一行；全部正常时居中显示一个大对勾。

尺寸或字号不满足上述条件时沿用下面的分页布局。2×1 每页一个来源；其他状态组件每页最多两个来源。4×3 在一至两来源时保留详细信息。三来源且宿主至少 330×240 dp 时，用量改为三列等高，每项额度画成环形仪表，百分比居中，下方一行为名称和重置时间（当天显示时刻，否则显示月/日；Cursor 显示周期剩余），单币种 DeepSeek 以赠送 / 充值占比环显示总余额，环沿列高均匀分布，列底备注省略，时间贴在列底；状态改为三行通栏。四来源采用四格摘要。空间不足改为两来源；4×3 高度不足 220 dp、2×2 宽度不足 160 dp 或超过 130% 字号采用单来源分页。单独占一行的来源横向铺满，不留空列。

点击箭头循环翻页，每个组件独立保存来源锚点，来源删除后回到可用页；删除组件清理对应偏好。翻页只重绘缓存，点击来源打开应用对应页面和来源。Android 12+ 根据宿主提供的尺寸生成响应式 RemoteViews，旧平台根据可用尺寸范围选择布局。系统样例预览不读取凭据。

## 数据口径

- DeepSeek 显示原币种余额，不换算、不相加，也不推导百分比。只有一种币种时，同一列继续显示赠送和充值；余额是否足够调用与公开服务健康分开。
- Kimi Code 显示接口实际返回的额度窗口、重置时间与加量包；缺失不补零，不一致保留提示。空间不足显示剩余项数。
- Cursor 分列自有模型与其他模型两条额度，本周期合计写在额度下方。Codex 保留各窗口额度条及重置时间。额度条使用位图，避免宿主重新应用 RemoteViews 后比例串用。
- 状态全局摘要覆盖所有已配置来源，而非只有当前页。缺失、组件不完整或超过十五分钟的数据不会形成“全部正常”；已知故障优先。组件列表异常优先，溢出明确提示。

## 缓存与刷新

先读缓存，再由 JobScheduler 周期任务刷新：周期十五分钟，只在每个周期的最后五分钟内运行，相邻两次至少隔十分钟。计划刷新只跳过九分钟内的缓存，所以到点的那次会真正拉取；新鲜度若与周期同为十五分钟，到点的那次常因“还新鲜”跳过，数据会旧到半小时以上。已排好的周期任务参数不同时，升级后会按新参数重排。只有用量组件时不查询状态接口，只有状态组件时不查询账户用量；未配置来源不发请求。没有组件时停止组件任务。

点刷新按钮后，这次广播会一直托住进程，直到强制刷新画出结果，最多十五秒。广播结束前进程不会被冻结或断网，期间任何缓存重绘都保留「正在刷新」。同时排一个兜底任务，它和按钮那一轮谁先拿到刷新锁谁去拉取；另一方发现已被成功覆盖就直接结束，不重拉也不重画，免得页脚的「已更新」被改回「缓存」。按钮那一轮没拿全时，由兜底任务强制补齐。十秒冷却内再点，上一轮还在刷新就继续显示「正在刷新」，否则提示稍后再试。

一个来源慢不拖住全部组件：按钮那一轮每个来源最多等十秒，后台任务最多等十五秒，没返回的先用缓存画上。请求本身继续跑完并写入缓存，后台任务随后再补画一次。

HyperOS 熄屏后会冻结后台应用，周期任务推迟到亮屏、组件可见时补跑。应用退到后台时，系统会停掉正在执行的任务；没有任务或广播托住的后台进程还会被切断网络。省电策略设为「无限制」后后台网络不再被切断，但熄屏冻结仍可能发生。

单个组件或单个尺寸画不成只跳过那一格，其余组件照常重绘；4×3 总览面板失败时退回原来的分页卡片。跳过绘制、宿主拒绝更新，以及按钮刷新超时或失败都写入 `AgenTWidget` 日志，桌面停在旧画面时可以据此定位。刷新执行槽若因任务被取消漏掉收尾，十分钟后按已结束重新排期，避免之后再也排不到刷新。

跟随系统主题时，颜色按绘制当时的深浅色写入。进程仍在则配置变化立即用缓存重绘；进程不在则留到下一次推送，那次绘制使用当时的系统模式。浅色表面上过淡的文字和描边会加深，避免浅色壁纸上融成一片。

DeepSeek / Kimi 的应用与组件使用共享 Repository 合并同一凭据修订号的在途请求。密钥、区域、最新账户响应和错误类别共用加密记录；替换或删除连接后旧响应和旧错误不能恢复缓存。失败保留原更新时间，不伪装成新数据。分页偏好只保存组件与来源 ID。

应用同步或连接变化后推送缓存重绘，保留首帧后系统入口维护。通知仍沿用现有 Cursor / Codex 范围。账户接口和状态筛选见 [官方来源](official-providers.md)，通知调度见 [通知行为](notifications.md)。

## 验证

通过标准构建入口运行单元测试和 RemoteViews 原生绘制，覆盖七种组件、中英文、深浅色、最小尺寸与 200% 字号，同时检查文本测量与父视图裁切。图库入口见 [界面验收](ui.md#界面验收)。JVM 绘制结果不等同于实际 OEM 桌面截图；认证请求使用合成夹具验证。
