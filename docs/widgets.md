# 桌面小组件

七种组件保留原 provider 标识，升级后无需重新添加。两种用量组件支持 Cursor、Codex、DeepSeek API 和 Kimi Code。五种状态组件使用这四家的公开健康数据。

## 配置与布局

只展示已保存连接的来源，顺序为 Cursor、Codex、DeepSeek、Kimi Code。认证失败的已保存连接仍显示修复提示；残留公共状态缓存不能让未配置来源重新出现。全部未配置时点击统一配置入口。指向已移除来源的分页锚点在启动时清除。

宿主至少 250×200 dp 且字号不超过 130% 时，4×3 组件改为单页总览，不再分页：

- 用量（二至四个来源）：标题写明「已用额度」，大标题突出用量最高的额度窗口，例如「Codex 5小时 · 已用 100%」，副标题给出该窗口的重置时间和同来源另一窗口。下方每个来源一行，每个百分比前都标注窗口名称（自有 / 三方、5小时 / 每周），并配有额度条。余额只显示币种和金额；单币种 DeepSeek 在金额下注明赠送 / 充值，不再写「余额可用」。空间不够时依次省略大标题的说明行、副标题和整个大标题。
- 状态（一至四个来源）：可在「设置 → 系统入口」的 4×3 服务状态预览下选择三种版式，切换后已放置的组件立即用缓存重绘。「总览列表」先用大标题给出结论，再逐行列出各来源的组件正常数和状态。「四格信号灯」每个来源一格，异常格染色并排在前面，三个来源时异常来源占满首行。「异常置顶」只展开有问题的来源，卡片写明事件、持续时长和受影响组件，正常来源折叠成一行；全部正常时居中显示一个大对勾。

尺寸或字号不满足上述条件时沿用下面的分页布局。2×1 每页一个来源；其他状态组件每页最多两个来源。4×3 在一至两来源时保留详细信息。三来源且宿主至少 330×240 dp 时，用量改为三列等高，每项额度画成环形仪表，百分比居中，下方一行为名称和重置时间（当天显示时刻，否则显示月/日；Cursor 显示周期剩余），单币种 DeepSeek 以赠送 / 充值占比环显示总余额，环沿列高均匀分布，列底备注省略，时间贴在列底；状态改为三行通栏。四来源采用四格摘要。空间不足改为两来源；4×3 高度不足 220 dp、2×2 宽度不足 160 dp 或超过 130% 字号采用单来源分页。单独占一行的来源横向铺满，不留空列。

点击箭头循环翻页，每个组件独立保存来源锚点，来源删除后回到可用页；删除组件清理对应偏好。翻页只重绘缓存，点击来源打开应用对应页面和来源。Android 12+ 根据宿主提供的尺寸生成响应式 RemoteViews，旧平台根据可用尺寸范围选择布局。

系统组件选择器里的预览就是组件本身：七种组件各用真实的渲染器配合固定样例数据画出预览图，四家来源都在、状态全部正常，更新时间统一写成 09:41，按中英文与深浅色各一张，由桌面按系统语言和深浅色挑选。HyperOS 选择器按格子宽度缩放预览、顶端对齐，超出预览区（约 228×200）的部分从底部裁掉，所以 2×2 按 174×150 dp 画，与预览区同比例，底部的更新时间不会被裁。HyperOS 等桌面只显示这张静态图；Android 15 起另行推送同样内容的生成式预览，应用内「系统入口」的预览也用同一份样例。此前 Android 12+ 上只有一个写死数字的四格文字布局，跟真实组件毫不相像。样例预览不读取账号或凭据；图片的生成与校验见 [构建说明](../build.md#组件选择器预览图)。

## 数据口径

- DeepSeek 显示原币种余额，不换算、不相加，也不推导百分比。只有一种币种时，同一列继续显示赠送和充值；余额是否足够调用与公开服务健康分开。
- Kimi Code 显示接口实际返回的额度窗口、重置时间与加量包；缺失不补零，不一致保留提示。空间不足显示剩余项数。
- Cursor 分列自有模型与其他模型两条额度，本周期合计写在额度下方。Codex 保留各窗口额度条及重置时间。额度条使用位图，避免宿主重新应用 RemoteViews 后比例串用。
- 状态全局摘要覆盖所有已配置来源，而非只有当前页。缺失、组件不完整或超过十五分钟的数据不会形成“全部正常”；已知故障优先。组件列表异常优先，溢出明确提示。

## 缓存与刷新

先读缓存，再由 JobScheduler 周期任务刷新：周期十五分钟，只在每个周期的最后五分钟内运行，相邻两次至少隔十分钟。计划刷新只跳过九分钟内的缓存，所以到点的那次会真正拉取；新鲜度若与周期同为十五分钟，到点的那次常因“还新鲜”跳过，数据会旧到半小时以上。只有用量组件时不查询状态接口，只有状态组件时不查询账户用量；未配置来源不发请求。没有组件时停止组件任务。

所有组件任务结束时都不要求系统重排，被系统停掉时也不要求。系统重排按指数退避累计失败次数：1.7.0 的周期任务每次有来源没拿全都要求重排，实机上被推到四个多小时才跑一次，自动刷新形同停止。周期任务没拿全就等下一个周期。周期任务的 extras 记有排法版本，参数或版本不同时升级后重排一次，旧任务的退避计数随之清零；参数一致时不重排，免得每次打开应用都推迟周期。

点刷新按钮后，这次广播最多托住进程七秒，期间进程不会被冻结或断网。组件点击以前台广播送达，十秒内不交还就会被判 ANR，进程随之被杀。1.7.0 托住十五秒，实机上两次在第十秒被杀，这一轮刷新随进程一起丢失。按钮那一轮与同时排上的刷新任务谁先拿到刷新锁，谁就强制拉取，五秒时先画一次。同一个请求只强制一次，不论那一轮是否拿全；后到的刷新任务按缓存新鲜度补拉，仍在途的请求直接加入，不另发；广播里那一轮后到时直接结束，不再按缓存重画。「正在刷新」保留到第一次画出结果，最长二十秒。十秒冷却内再点，上一轮还在刷新就继续显示「正在刷新」，否则提示稍后再试。

一个来源慢或出错都不拖住全部组件。各来源并行拉取、各自写缓存：按钮触发的那一轮五秒先画，其他后台任务十五秒先画，都从拿到刷新锁时起算；到点没返回、抛了异常，或加入的共享请求被别处取消的来源，只让它自己先用缓存画上，不会取消其他来源，也不会让这一轮作废，只有这一轮本身被取消时才整轮停下。每家连接的加密缓存读不出来时，也只让那一家显示存储错误。请求本身继续跑完并写入缓存，后台任务随后加入这些请求再补画一次。补画那一轮会一直等慢来源回来，但随时为刷新按钮让路：按下按钮时，正持有刷新锁的非强制那一轮立刻用已有结果画完并放开锁，按钮那一轮马上开始强制拉取；按钮刷新还在等结果（二十秒内）时才开始的后台轮次一开始就让路。实机上一个状态接口的 TLS 握手拖了四十多秒，此前期间按下的刷新排在它后面，21 秒后才出结果。一次性刷新没拿全时，一分钟后补拉一次，仍没拿全五分钟后再补一次，之后交给周期任务；补拉不强制，只重拉过了新鲜期的来源。被系统停掉的任务同样改由补拉接手。

页脚时间：没有数据的来源（例如需要更新连接）不参与判定，否则它会让整块组件一直显示「缓存」。新鲜期（九分钟）内读出的缓存算「更新」。只要还有来源在新鲜期内，4×3 总览页脚就显示其中最近的更新时间，过了新鲜期仍在用缓存的来源附在后面，例如「更新 16:38 · DeepSeek 14:41 缓存」：一个来源一直失败，不会让刚更新的其他来源跟着显示成「缓存」。全部来源都过了新鲜期时才整块标「缓存」，显示其中最旧的时间。分页卡片和旧版状态组件按来源分别显示时间，规则相同。

HyperOS 熄屏后会冻结后台应用，周期任务推迟到亮屏、组件可见时补跑。应用退到后台时，系统会停掉正在执行的任务；没有任务或广播托住的后台进程还会被切断网络。省电策略设为「无限制」后后台网络不再被切断，但熄屏冻结仍可能发生。

单个组件或单个尺寸画不成只跳过那一格，其余组件照常重绘；4×3 总览面板失败时退回原来的分页卡片。跳过绘制、宿主拒绝更新、按钮刷新超时或失败、后台轮次为按钮刷新让路、补拉安排、周期任务没拿全，以及任务被系统停止（含停止原因）都写入 `AgenTWidget` 日志，桌面停在旧画面时可以据此定位。每一轮没拿全时另记一行，列出是哪些来源以及原因：HTTP 状态码、异常类名、到点未返回（late）或加入的共享请求被别处取消（cancelled）。日志只含来源名，不含账号、凭据或响应内容。刷新执行槽若因任务被取消漏掉收尾，十分钟后按已结束重新排期，避免之后再也排不到刷新。

跟随系统主题时，颜色按绘制当时的深浅色写入。进程仍在则配置变化立即用缓存重绘；进程不在则留到下一次推送，那次绘制使用当时的系统模式。浅色表面上过淡的文字和描边会加深，避免浅色壁纸上融成一片。

DeepSeek / Kimi 的应用与组件使用共享 Repository 合并同一凭据修订号的在途请求。密钥、区域、最新账户响应和错误类别共用加密记录；替换或删除连接后旧响应和旧错误不能恢复缓存。失败保留原更新时间，不伪装成新数据。分页偏好只保存组件与来源 ID。

应用同步或连接变化后推送缓存重绘，保留首帧后系统入口维护。通知仍沿用现有 Cursor / Codex 范围。账户接口和状态筛选见 [官方来源](official-providers.md)，通知调度见 [通知行为](notifications.md)。

## 验证

通过标准构建入口运行单元测试和 RemoteViews 原生绘制，覆盖七种组件、中英文、深浅色、最小尺寸与 200% 字号，同时检查文本测量与父视图裁切。图库入口见 [界面验收](ui.md#界面验收)。JVM 绘制结果不等同于实际 OEM 桌面截图；认证请求使用合成夹具验证。
