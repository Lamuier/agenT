# 桌面小组件

七种组件保留原 provider 标识，升级后无需重新添加。两种用量组件支持 Cursor、Codex、DeepSeek API、Kimi Code 和实验性 Antigravity 直连。五种状态组件保留四家的公开健康数据；已配置的 Antigravity 显示状态未接入，不将额度接口成功当作服务正常。

## 配置与布局

只展示已保存连接的来源，顺序为 Cursor、Codex、DeepSeek、Kimi Code、Antigravity。认证失败的已保存连接仍显示修复提示；残留公共状态缓存不能让未配置来源重新出现。全部未配置时点击统一配置入口。

2×1 每页一个来源；其他状态组件每页最多两个来源。4×3 在一至两来源时保留详细信息，三至五来源且宿主至少 330×240 dp 时采用四格摘要；空间不足改为两来源；4×3 高度不足 220 dp、2×2 宽度不足 160 dp 或超过 130% 字号采用单来源分页。单来源占满内容区。

点击箭头循环翻页，每个组件独立保存来源锚点，来源删除后回到可用页；删除组件清理对应偏好。翻页只重绘缓存，点击来源打开应用对应页面和来源。Android 12+ 根据宿主提供的尺寸生成响应式 RemoteViews，旧平台根据可用尺寸范围选择布局。系统样例预览不读取凭据。

## 数据口径

- DeepSeek 显示原币种余额，不换算、不相加，也不推导百分比。余额是否足够调用与公开服务健康分开。
- Kimi Code 显示接口实际返回的额度窗口、重置时间与加量包；缺失不补零，不一致保留提示。空间不足显示剩余项数。
- Cursor / Codex 保留独立额度条及重置时间。额度条使用位图，避免宿主重新应用 RemoteViews 后比例串用。
- Antigravity 保留接口返回的模型组 / 周期名称、实际已用比例与重置时间。第五来源可独立翻页；未配置隐藏，授权失败保留缓存和修复提示，缺失额度不补零。身份验证、刷新及接口边界见 [Antigravity](antigravity.md)。
- 状态全局摘要覆盖所有已配置来源，而非只有当前页。缺失、组件不完整或超过十五分钟的数据不会形成“全部正常”；已知故障优先。组件列表异常优先，溢出明确提示。

## 缓存与刷新

先读缓存，再通过现有 JobScheduler 约十五分钟调度刷新。只有用量组件时不查询状态接口，只有状态组件时不查询账户用量；未配置来源不发请求。没有组件时停止组件任务。手动刷新沿用十秒冷却，系统节电或网络限制可能延迟任务。

DeepSeek / Kimi / Antigravity 的应用与组件使用共享 Repository 合并同一凭据修订号的在途请求。密钥、区域、最新账户响应和错误类别共用加密记录；替换或删除连接后旧响应和旧错误不能恢复缓存。失败保留原更新时间，不伪装成新数据。分页偏好只保存组件与来源 ID。

应用同步或连接变化后推送缓存重绘，保留首帧后系统入口维护。通知仍沿用现有 Cursor / Codex 范围。账户接口和状态筛选见 [官方来源](official-providers.md)，通知调度见 [通知行为](notifications.md)。

## 验证

通过标准构建入口运行单元测试和 RemoteViews 原生绘制，覆盖七种组件、中英文、深浅色、最小尺寸与 200% 字号，同时检查文本测量与父视图裁切。图库入口见 [界面验收](ui.md#界面验收)。JVM 绘制结果不等同于实际 OEM 桌面截图；认证请求使用合成夹具验证。
